Before you begin, a little background on testing for context. Test cases are descriptions of a scenario, the inputs, the steps and the expected result, that a tester can execute to check whether a piece of software behaves as intended. Good test cases cover the happy path, the boundaries of every rule, and the error cases. They are independent of each other, they are repeatable, and each one checks one thing. A test case is not the same as a test script; a script is code, a case is a description. In this task we want cases, not scripts.

The system under test is Helios OrderCore, a small Python and FastAPI order management API. Orders are created with POST /orders. The service validates the request, allocates an order identifier of the form ORD-nnnn starting from ORD-1001, sets the status to pending and stores the order in memory. An order has a customer (non-empty string), an optional currency defaulting to GBP, and at least one order line. Each line has a SKU (non-empty), an optional description, a quantity greater than zero, and a unit price in pence which is zero or more. Money is always a whole number of pence, never a float. A request that fails validation is rejected with HTTP 422 and nothing is stored. A request that passes returns HTTP 201 with the created order.
